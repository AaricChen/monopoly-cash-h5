# 纸币与结算系统

本作最大差异化：**不默认自动扣减余额**，而是通过可视化纸币与双向找零完成交易。

### 玩家资产双重表现

- **总额**：所有手持纸币折算后的 `cashTotal`（便于快速判断能否支付大额）。
- **张数分布**：`wallet: Record<Denomination, count>`，UI 与结算逻辑均以张数为准。

银行（Bank）同样维护纸币库存（含找零能力）；可选规则：银行纸币无限 vs 有限（高阶策略）。

## Wallet Panel（抽屉式钱箱）

触发时机：买地、交租、罚款、卡面金额、抵押赎回等任何「需付现金」操作。

交互要点：

- 按面额分区摆放纸币，支持拖拽到「支付区」。
- 支付区实时显示「已选总额 / 应付金额 / 差额或待找零」。
- 确认前不可关闭面板（除非取消交易并回滚 UI 状态）。

## 三种交易模式

### 1. 支付模式（付款方）

场景：买地、交租、向银行/玩家付款。

流程：

1. 系统给出应付金额 `amountDue`。
2. 付款方拖拽纸币至支付区，使 `selectedTotal >= amountDue`。
3. 若 `selectedTotal === amountDue`：直接进入收款确认（无找零）。
4. 若 `selectedTotal > amountDue`：进入**找零子流程**，差额 `change = selectedTotal - amountDue`。

示例：应付 $140，可拖 1×$100 + 2×$20；或拖 1×$500 → 待找零 $360。

### 2. 找零模式（收款方）

收款方（银行或其他玩家）界面弹出**找零区**：

- 需从自己的钱箱（或银行库存）选出纸币组合，使找零总额 **恰好等于** `change`（练习模式）。
- 确认后将找零纸币加入付款方钱包，支付区大钞扣除并转入收款方（或销毁进银行，按规则定）。

### 3. 收款确认

双方（或系统作为银行单方）确认后：

- 原子更新双方 `wallet` 与地产/负债状态。
- 写入本地存档 checkpoint。

## 心算校验与练习机制

可配置全局或每局设置：

| 模式 | 名称 | 行为 |
|------|------|------|
| A | 练习模式 | 支付总额须 ≥ 应付；找零组合须 **精确等于** 待找零；否则提示「金额不符，请重新计算」，不可确认。 |
| B | 娱乐模式 | 提供「一键凑钞」「智能找零提示」；可按提示点选完成，降低低龄或慢算玩家卡关概率。 |

### 练习模式额外建议

- 可选显示「心算步骤」折叠区（不直接给答案，只提示如「还差 $40」）。
- 连续错误 N 次后建议切换娱乐模式（非强制）。

## 边界情况

- **现金不足**：不打开正常支付完成流，转「抵押/变卖」强制流程（见 [经典机制还原](04-classic-mechanics.md)）。
- **找零方库存不足**：若采用有限银行纸币，需触发「换零」或规则说明（MVP 可简化为银行无限供应找零纸币）。
- **取消支付**：回滚 UI 选中状态，不改变棋盘状态机阶段，直至玩家重新凑钞或选择破产流程。

## 与状态机的关系

在 `PAY_*` / `CHANGE_*` 相关状态下，**未完成的找零会阻塞** `END_TURN` 与下一阶段。详见 [回合状态机](07-game-state-machine.md)。
